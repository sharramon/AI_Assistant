What changes

  1. Remove the ~$ everywhere it is shown or sent: - Contract: SessionUsage.cost_usd is dropped. - Counting: ClaudeSession stops reading total_cost_usd, and cost_usd goes away. session_usage and subagent_usage stop sending it. - Usage module: UsageLedger and the usage.total / agents / mine results drop cost_usd. - Talker: the [Usage] line and describe_usage drop the ~$, and the Talker's prompt text about it goes too. - Temp UI: the header total, the dropdown rows and the tooltip drop the ~$. - Tests: test_usage, test_agents and fake_claude drop it. - Docs: the usage module, api/agents.md (SessionUsage), api/infra.md, api/README.md, module-library.md, agents/runtime.md and modules/README.md.
  2. Labels. In the line: worker: context 45k (last call), used 3.2M (incl. resent cache). In the Talker's prompt and the UI tooltip, the full meaning: "context" is the size of the latest call, about what each next call resends. "Used" adds up every call's input, cache writes, cache reads and output since launch, so cached context counts again on every call. It measures work done, not new text.
  3. Restarts can't drop earlier totals. Today the ledger guesses that a new session started when any number goes down. If a fresh session's first report is already bigger in every number, the old totals are lost. The fix: SessionUsage gets a session id, a new one per ClaudeSession object. When the id changes, the ledger banks the old totals. Restarts of the process inside one session object already carry over, as today.
  4. Sub-agent counts. Checked: they cover only the last call. In the log of 2026-11-06 (main_assistant.jsonl, line 392), an Explore sub-agent with 41 tool uses reported input 2, cache write 707, cache read 98,361, output 7,168, which adds up to its totalTokens of 106,238. That is the shape of one call: fresh input of 2 and about 99k of context. A run of about 40 calls would report millions. A debugger with 3 tool uses showed the same shape. So today a sub-agent's row shows roughly its final context, not its work. - Fix (recommended): take sub-agent tokens from each turn's result. Its modelUsage includes sub-agents (verified 2026-11-05 in usage tallies), and its usage is the parent's own calls. The difference is all the sub-agents' tokens for that turn. If one sub-agent ran in the turn, its row gets it. If several ran, it's shared in proportion to their last-call sizes, and the parent's total is exact either way. - Unconfirmed until built: whether modelUsage counts a sub-agent's every call when it uses tools. The 2026-11-05 check used a sub-agent with no tools. A test on the real claude tool comes first in the build.
  5. The temp UI's header follows the selected tab (a bug the user found, 2026-11-07). Clicking through agent tabs didn't switch the worker and Talker contexts to that agent's pair. Now the page keeps every agent's own context by id (SessionUsage with kind = "claude"; sub-agents and tools left out). The header shows the selected tab's worker (<id>) and its Talker (talker for the Main Assistant's tab, talker:<id> for a helper's). Used shows that pair's tokens since launch, with their sub-agents, from the usage module's rows. It redraws on a tab change, on new usage for any agent and on each new tally.
