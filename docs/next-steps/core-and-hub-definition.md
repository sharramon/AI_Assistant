- [x] **V3. The lifecycle in full** (`core/lifecycle.py`, 423 lines; `core/registry.py`, 85 lines). **V**, with details the docs didn't give.
  - **Cycle check: two places.** At launch, `resolve_modules` sorts by `requires`, `optional` and `needs` and raises `StartupError("Circular dependency …")` when no module is ready (`registry.py:65-81`). At runtime, `_activate` carries the chain and refuses a module already in it (`lifecycle.py:274-275`), over `requires` and `needs` only (`:286-305`; `optional` isn't followed at runtime).
  - **Start order:** at launch, every module is `init`ed in dependency order first, then every one is `start`ed in the same order (`lifecycle.py:56-79`). A module that fails is skipped, unless it is the only provider of a contract another healthy module requires: then the whole start fails (`_skip`, `:400-410`). At runtime, `_activate` turns on the sole provider of each required contract and each `needs` module first, then inits and starts the one asked for (`:268-320`).
  - **Stop order:** reverse activation order (`:81-88`; `_active` is insertion-ordered, `:45-46`). Turning one off refuses while an active module needs it, unless `with_dependents`, which stops them in reverse first (`:336-353`). Each stop has a timeout, then the context is closed whatever happened (`_stop_one`, `:384-393`), which undoes the module's registrations.
  - **Reload path** (`:121-170`): wait until `busy()` is None (up to `reload_idle_timeout`, default 300 s; `now` skips it, `:125-128`); refuse shared code (`loader.check_reloadable`, `loader.py:135-141`); stop the modules that depend on it (reverse), `export_state`, stop it; drop its package from `sys.modules`, import it fresh; start the new class with the exported state as the handover; on any failure, put the old modules back and start the old code with the same state (`_roll_back`, `:226-237`); then restart the dependents that were stopped (`_restart`, `:262-266`). An inactive module only gets its class swapped.
  - **No permission check anywhere in the lifecycle.** Every ask is in the core's menu (`core/directory.py`): `modules.add`, `modules.remove` and `modules.off` with dependents call `permissions.request` (`directory.py:79, 94, 106`); `modules.on` only sets `ACTING_FOR` (`:67-74`); **`modules.reload` asks nothing** (`:85-88`). The commands `ReloadModule`, `AddModule`, `RemoveModule`, `ActivateModule`, `DeactivateModule` are handled by the core (`app.py:92-101, 207-216`) with no ask, so a module that sends them itself (not through the menu) skips even the menu's asks (see V10).

- [x] **V5. The event bus internals** (`core/bus.py`, 89 lines). **V.**
  - **Bounded subscribers:** every subscription has its own queue (`maxsize` = `core.event_queue_size`, default 100, `app.py:79`) and exactly one worker task (`bus.py:16-36`). `publish` never waits: it offers the event to each matching queue, and **a full queue drops that event for that subscriber only**, with a warning (`bus.py:78-82`). Each handler run has a timeout (`core.event_handler_timeout`, default 10 s), after which it is cancelled and logged; an exception is logged; the worker carries on (`bus.py:45-57`). Matching is by `isinstance`, so a subscription to `Event` gets everything (`:66-67`).
  - **A module that is turned off, reloaded or removed:** `_stop_one` calls the module's `stop()` first, then `ctx.close()` (`lifecycle.py:384-393`). So events keep arriving while it stops. `close` unsubscribes every subscription (`context.py:166-175`), and `unsubscribe` cancels the worker (`bus.py:72-76`): **events still queued for it are dropped, and a handler in the middle of a run is cancelled.** Nothing is redelivered to the reloaded copy; only what `export_state` handed over survives. After close, its `publish` is dropped silently and its `send` is refused (`context.py:103-108, 119-121`).
  - **No sender on an event:** `Message` has only `id`, `correlation_id`, `timestamp` (`contracts/messages.py:17-24`); `Event` adds nothing (`:31`). The one exception is the named event: `publish_named` stamps `source` with the module's id and refuses a name not starting with it (`context.py:67-76`). **But** `ctx.publish` takes any `Event`, so a module can build a `ModuleEvent(name="cv.job_submitted", source="cv")` by hand and publish it: the stamp is a convention, not a check (`ModuleEvent` says "never built by hand", `messages.py:115-127`).

- [x] **V6. The Hub's side of the door: how `mcp_config(caller)` proves the caller, and what stops the door's host naming another caller.** **V** for the token; **D**: the proof is weaker than "a caller the session can't fake" suggests.

## 4. The proposed definition

**Core** = what the app can't start without, plus the ports. In `src/assistant/core` (and `contracts`, `infra`, `app_kit` as shared code): the host (`App`), the registry and loader, the lifecycle, the router, the bus, the container, config and logs, the directory with the core's menu, generated files, the permissions handler, **and, new: the door and the callers registry**.

**Seven ports** (what a module's `ModuleContext` gives it; today there are six roads, the seventh is new):

| # | Port | Road | Checked by the core (proposed) |
|---|------|------|-------------------------------|
| 1 | **Commands** | `send` / `handle` through the router | handler strict (today); `sends` strict and the **sender stamped** on every command (new); control commands list who may send them (new) |
