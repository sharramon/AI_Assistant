## Decisions taken (the recommended answers)

- **D1 (a):** the core hosts the door, as part of the Tools port. `mcp_config(caller)` gives a config only for the asking module itself or the agents it claimed; menus are not reachable as a plain `IToolProvider` contract with a free caller (G11, G16).
- **D2 (a):** a new Callers port in the core holds agent names, kinds, each caller's permission mode, and who is "you" (one list; task_agents' own `YOU` goes, G18).
- **D3 (a):** the sender is stamped on every command; `sends` and `publishes` strict; control commands only from "you" callers (and the core). Also: the control methods of `ITaskAgent` checked against Callers (G12), answer handlers check the sender, `local_guard` on temp_ui's and voice_notes' pages (G10), `ctx.publish` refuses a hand-built `ModuleEvent` (G15).
- **D4 (a):** one checked gate in `dispatch_tool`: item `callers`, then items marked risky ask through the permissions handler unless the caller is in Auto; agents keep Claude Code's own asks.
- **D5 (a):** `ResetRequested`, `ShutdownRequested`, `AgentNotice` become commands (the handler's own `AgentNotice` too).
- **D6 (a):** the review becomes a listener that adds notes to a card; the core never starts a task.
- **D7 (a):** the boundary tests (rules 1 to 3) come before any move.
