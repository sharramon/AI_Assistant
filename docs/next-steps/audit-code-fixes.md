## Build status

Built 2026-11-13. Nothing restarted or reloaded; not committed.

- **Items 1-5:** as in the table. Item 1 also gets a test (`test_the_core_line_names_every_core_menu_item`) so `CORE_LINE` can't miss a `modules.*` item again.
- **Item 6, generated, not hand-completed (the user's decision 2):** `App.offers()` names what the core offers from the tables `start` registers: `_handlers` (its commands), `_provides` (its contracts, new: `IAgentNames`, `IModuleDoor`, now one table `start` loops over), `core_specs()` (the `core` menu `GetMenu` answers; was `_core_specs`) and `App.PUBLISHES` (`ModuleStateChanged` plus `PermissionsHandler.PUBLISHES`, the card events). `scripts/build_docs.py` builds a bare `App` (no modules, door off, grants file in a temp folder) and renders the row with `core_line(core_offers())`; the hand-written `CORE_LINE` there is gone. Tripwires in `tests/test_module_docs.py`: the page's core row names everything `offers()` returns, and every literal `publish(X(...))` in the core (but `context.py`, a module's own events) is in `App.PUBLISHES`.
- **Items 7-8, changed from decision 1:** `task_agents` is a core module, and a core module's settings never name an add-on (`tests/test_boundaries.py`, rule 2: values, not comments). So the prompt can't name cv. It now says to find the module whose menu has the `rezi.*` items (`list_modules`, `show_menu`) and read that module's tools page (`modules.docs`), which is cv's tools page. The comment names `cv/docs/tools.md` and says why. The description says "the rezi.* items on the module door".
- **Item 9:** unchanged, a pointer to restructuring step 7.
- **Checks:** 1002 tests passed (2 deselected, the usual 4 unclosed-pipe warnings); ruff clean; docs rebuilt (the core row generated, `ModuleStateChanged` once in job_search's row).
