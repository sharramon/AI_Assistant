2 · Why that is wrong

  • 1 A module's app sits outside its folder, so deleting the folder leaves the app behind.
  • 2 Config, tests, docs and packages are kept centrally, so adding or removing a module means editing shared files.
  • 3 Module tests import central test files, so a module can't be tested on its own.
  • 4 The core's contracts and infra hold an add-on's types (the viewer's events, SHOW handling).
  • 5 Modules name other modules in prompts and code but never declare it, so nothing warns you before a delete.
  • 6 Core modules name add-ons (the viewer, cv_agent), so deleting an add-on can break the core.

3 · Ideal: a core group, add-ons in modules/, plus config/ and generated/

new or moved unchanged

core/ ships with the app · never deleted · works with zero add-ons

host: lifecycle · router · events · directory · permissions generic contracts + infra only public test kit (from tests/support) reads "needs" lists
agent_hub/ · talker/ · main_assistant/ · console_io/own docs · tests
temp_ui/own docs · tests · a snip/open slot an add-on can fill
voice_in/voice_service app · docs · tests · voice packages
task_agents/docs · tests · kinds as defaults
usage/docs · tests · UsageLedger

modules/ add-ons

one self-contained folder each · downloaded or deleted whole

job_search/code · docs · tests · needs cv
html_viewer/code · viewer app · docs · tests · its events · SHOW handling
voice_notes/code · page · docs · tests · needs voice_in

config/

your choices only · kept across downloads
one file per module which add-ons are on local overrides saved grants (now data/permissions.toml)

modules/cv/
├─ module.py · worker.py · …   code
├─ module.toml                 defaults
│    needs = []                dependency list (new)
│    [agent] cv_agent          ← agent_hub's section
├─ app/                        ← src/cv_tool
│    cv_tool.toml              ← src/cv_tool
├─ tests/                      all cv tests, on the core test kit
├─ docs/                       its pages
└─ packages                    pymupdf · ruff rule ← pyproject

Rule: nothing of cv lives outside modules/cv/, except your own choices in config/cv.toml.

Delete modules/cv/ and nothing of cv is left behind.

Every other add-on (job_search, html_viewer, voice_notes) has the same shape, and so do the core modules that own an app or tests.

New: today requires lists contracts (voice_notes requires IVoice), not modules. A list of the modules a module needs is new.

Unlike Unity: saved grants are your decisions, so they go in config/, not generated/. Modules load and reload while the app runs, with no build step.

4 · Why that is right

  • A Download or delete one add-on folder and the whole module comes or goes. Your choices stay in config/.
  • B The core group knows no add-on by name, so it runs with none, and any add-on can be swapped.
  • C The "needs" lists point only toward the core or other add-ons. They show what breaks before a delete, and bring cv along with job_search.
  • D Each module tests alone with the core's public test kit.

5 · How it is used

  • Add: drop or download a folder, and the core reads its module.toml and adds it to the list.
  • Reload: the same folder's new code is swapped in while the app runs (as today).
  • Remove: it warns if another module needs it, then deletes the folder and updates the list.
