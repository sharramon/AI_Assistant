The app's piping

Every way data gets in and out of the app: who sends what, by which path, and which checks it passes. Today, checked against the code, then a suggestion. A proposal page: nothing in the app is changed. 2026-11-13. Source note: core-and-hub-definition (the definition page) and docs/next-steps/core-and-hub-definition.md.

Your ask: tools, events and contracts harden how data gets in and out, so every call and every card passes the core's checks (router, permissions, the caller's mode), and the Agent Hub is a module that does agent coordination only. Each decision card is tagged with the part it serves: calls, cards, Hub; the gaps G1 to G20 carry the same tags in the note.

In plain words: the door, the router, the bus and the contracts were built so that every call and every card goes through the core's checks. Today most of them do, but not all.

The biggest gap: the Agent Hub hosts the door, so a module, not the core, says which agent is calling. Commands carry no sender, so any module could switch an agent to Auto or answer a card. And the core's own Auto check asks the Hub, so it depends on a module being on.

What keeps track of which modules exist and what they do: the core, not the Hub. At launch find_modules reads the module folders; the LifecycleManager keeps every module's class, on or off, and its state; the directory (ListModules, GetMenu) reads from it; each module's own manifest and menu say what it does. Sections 1b and 2b follow one add-on from "I want to start recording voice notes" to its first event.

The suggestion: the door and a new Callers port (agent names, each caller's mode, who is "you") move into the core. Every tool call and every card passes one checked gate there. The router stamps the sender on every command. Events only notify, never control. The Agent Hub keeps agent coordination only: tasks, focus, held questions, delivery, milestones.

  • The door moves from the Agent Hub into the core (part of the Tools port). Agents reach modules even with the Hub off or reloading.
  • A Callers port in the core holds agent names (today IAgentNames in the Hub), each caller's kind and permission mode, and who is "you". SetPermissionMode is handled there.

  • The Agent Hub keeps tasks, focus, held questions, delivery, milestones, the message hold, rule 2 and its hub.* menu. Nothing else.
