Built today: a single app: the core, terminal 1 (talk), the Talker, the Main Assistant, the Agent Hub, and a temp UI (a web page with both, a stand-in for the chat window until a UI handler is designed). Terminals: one to talk in, one view-only window showing what the Main Assistant is doing; the chat window later gives the same with nicer UX. Summary

A highly modular personal AI assistant that serves as a long-term experimental platform. A small, stable core hosts an ever-changing set of independent modules (inputs, outputs, views, tools, background workers, and the AI orchestration itself) that can be added, replaced, or discarded with minimal changes elsewhere.

The style is a modular monolith using ports & adapters, dependency injection, and event-driven communication. The modules run in one process. Changing code means a rebuild and restart; turning existing modules on and off happens while the app runs (runtime module control: built in the core; a control panel and asking the Talker come later). Loading new code without a restart is not a goal. Independent deployment is, for parts that are useful on their own: such a part is its own app that the main app launches and talks to through two-way hooks, via a thin module (decisions). The HTML viewer is the first.

The core runs on a PC today and will later move to a server, so it must not assume a local desktop: configuration, secrets, and data paths come from config files and environment variables, and user-facing interfaces are modules or remote clients. Headsets (Quest 3) and smartglasses are remote clients that connect over the network.
