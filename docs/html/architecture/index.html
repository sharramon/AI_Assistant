Architecture

The whole project at a glance. Each part links to its own page; the public interface is in the API reference.

Bird's-eye view

The numbers are the three rules of the core line:

  1. The core is what the app can't start without: the host, the core modules, the one module door with its gate, and the seven ports. It names no add-on.
  2. Add-ons talk only through tools, events and contracts, never by importing each other's code.
  3. Arrows point one way: an add-on may need the core or another add-on; the core never names an add-on.

Summary

A modular personal AI assistant, built as a long-term experimental platform. A small, stable core hosts a changing set of independent modules (inputs, outputs, views, tools, background workers and the AI agents themselves), which can be added, replaced or dropped with little change elsewhere.

  • The core is the host (src/assistant/core/), the core modules (each module's docs/docs.toml says group = "core"), the one module door with its one gate (dispatch_tool), and seven ports: lifecycle, commands, events, contracts, the directory, permissions and callers (core).
  • Add-ons are every other module, one folder each: in the repo's src/assistant/modules/<id>/, or in a folder outside the repo named in [core] module_folders (modules).
  • The agents. The Talker talks with you, the Main Assistant does the work and coordinates, and helpers and module agents do jobs. They reach every module through one MCP door with three tools (list modules, show a menu, use an item), so each module costs them one line until they open its menu (agents). The Agent Hub is a core module that does coordination only: focus, tasks, held questions and messages. The door, the agent names and each agent's permission mode belong to the core (its Callers port).
  • The style is a modular monolith with ports and adapters: the modules run in one process, and a module's code is reloaded in place without a restart. A part that is useful on its own (the HTML viewer, the voice service, the CV Tool) runs as its own app, launched by its thin module through CompanionApp (decisions).
  • Where it runs: a PC today, a server later, so the core assumes no desktop. Config, secrets and data paths come from config files and environment variables; user-facing interfaces are modules or remote clients.
