Module library

Every module in one place: what it does and its interface (the tools on its menu, the commands it handles and calls, the events it publishes and listens to). Each name links to the module's own page. The data types are listed below the table, with links to their API entries. Back to the overview.

Hand-written from the code, checked 2026-11-04. Since 2026-11-05 the manifest carries the description, the commands (handles, sends) and the events (publishes, listens); generating the table from them is next (module system, chunk 2). A test (tests/test_module_docs.py) checks that every module has a row here and a page. It becomes generated once the manifests carry the data (generated later).

The core itself handles the module control commands (ListModules, ActivateModule, DeactivateModule, ReloadModule, AddModule), routes InvokeTool to the module that offers the tool, and publishes ModuleStateChanged.
