job_search: the job agent and its menu

Purpose

The job agent, bundled with its own module: one big agent (id job_search_agent) that works in the job project (job project), applies to one job per session and runs job searches, plus its job.* menu. Off at launch (turn it on with modules.on). Design: working together.

Wrapper

Field Value
id job_search
provides ITaskAgent, the job agent (only the Hub calls it)
requires / optional none
permissions agent.access: it asks for its config's access list when turned on (access lists)

Interface
Tools job.search(days): answers at once; the result reaches the caller as an AgentNotice at its next turn. A stub today: the notice says the runner isn't built
Handles nothing: the agent is called through ITaskAgent, the menu through InvokeTool
Calls ctx.permissions.request_set on start (through request_access); ReportTask; the Hub's menu through the door, as job_search_agent; IAgentNames (ProfileAgent claims the id on start, releases it on stop)
Publishes AgentActivity, AgentStateChanged, SessionUsage, PermissionModeChanged, AgentNotice
Listens to ResetRequested (for the job agent)

Owns and launches

  • Its access, asked for on start: start asks for the whole list in one request (request_access, subject job_search_agent). If the saved grant matches the list, the agent is built at once. Otherwise a card opens and the start ends with AccessPending, so the module stays off; your Allow turns it on. A denied card leaves it off. The agent is built from the config cut down to what you allowed, and anything outside it asks with a normal card.
  • Grants live (built 2026-11-06, after the restart): it listens to PermissionChanged for its subject (watch_grant) and calls set_access(granted_config(...)), so a widened grant reaches it with no off and on (an idle open session restarts once; a busy one at its next session). The agent may ask for more itself with permissions.request, and reads your snips with no card.
  • One ProfileAgent with the job prompt: one job per session; HANDOFF: instead of the project's handoff.ps1; never submit or send (the user submits); confirm before any search. Its claude process starts on its first task, a fresh one per task, in Manual.
  • Chrome: chrome = true starts its session with --chrome (the Claude in Chrome tools).
  • Searches: each job.search is a background task, cancelled on stop. A reload waits while the agent has a task or a search runs.
