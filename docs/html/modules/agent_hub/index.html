agent_hub: who is doing what

Purpose

Holds the authoritative task state and routes work between the Talker and the task agents, and keeps the focus (the agent you're talking to). Not an AI; launches nothing. On by default. Design: agents, working together.

Wrapper

Field Value
id agent_hub
provides / requires provides IModuleDoor, the agents' one MCP door to the module menus, and IAgentNames, the agent ids in use; requires nothing
optional ITaskAgent (every task agent; it never imports one)
permissions none
needs none (Manifest.needs, from its module.toml): a core module, it needs no other module by id
packages none

Config

Defaults in module.toml in this module's folder, with their comments; [modules.agent_hub] in the app's config (your config/local.toml) only overrides them, key by key (how a module's config is built). config/default.toml has no section for it. The keys: coordinator (default main_assistant), max_extra_agents (default 3: big agents besides the coordinator with an active task at once), named_only (an optional fallback list of agent ids a free-agent pick, hub.start with no agent_id, never lands on; empty by default. The usual place is the agent's own config: named_only = true in its section, read from AgentInfo.named_only; cv_agent sets it in cv's [agent], since its jobs come from cv.task. Anyone may still name such an agent), start_only_by (agent id → the only callers whose hub.start may start it; the Talker always may, and a free-agent pick skips these agents too; empty by default), door, door_host, door_port.
