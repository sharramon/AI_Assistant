agent_hub: architecture

Interface
Tools the Hub's menu: hub.agents, hub.status, hub.start, hub.send, hub.cancel, hub.focus, hub.answer, hub.mode (the Talker only; hub.mode is Manual only and sends SetPermissionMode to the core), hub.suggest_focus (the coordinator only)
Handles ListAgents, StartTask, GetTaskStatus, SendToTask, CancelTask, ReportTask, AnswerPermission, SetFocus, DeliverMessage, AgentNotice (passed to that agent's note), ResetRequested (the agent's own reset), ReviewAccessList (the access-list review)
Sends SetPermissionMode (from hub.mode, Manual only; the core handles it), AddCardNotes (the review's notes, to the core)
Calls the agents' ITaskAgent methods, including note (words for the coordinator's next turn) and reset; ctx.permissions.granted / ask (the message gate's cards)
Uses IAgentNames, the core's Callers
Publishes TaskUpdated, FocusChanged, FocusSuggested
Listens to AgentActivity (kept per task as a view, not state), AgentStateChanged and ModuleStateChanged (the focus check, then waiting messages try again), PermissionModeChanged (a switch to Auto that answered an agent's open card: its task is active again and the card closes)

Not the Hub's

Since 2026-11-13 the Hub does agent coordination only. These moved to the core:

  • The module door: the core hosts it (core/door.py, settings in [core.door]), opened before any module starts, so a Hub reload never touches it. See IModuleDoor.
  • The agent names: the core's Callers (core/callers.py) provides IAgentNames. Claims outlive a Hub reload, so export_state has no claims. The Hub uses it to look agents up.
  • The permission mode: the core handles SetPermissionMode (Auto only from you). The Hub only sends it from hub.mode (Manual) and listens to PermissionModeChanged to close the agent's open card.

Owns and launches

  • Task records: id, agent, text, parent task, TaskState (active or idle, then the ends), the held flag, the open question with its kind and context key, recent activity. State changes only from commands, so dropped events can't corrupt it. An ended record lets go of its agent object (holder), and only the last 20 finished records stay (KEEP_FINISHED); a held one and an open task's parent always stay. They live in memory only: an app restart starts empty.
  • Questions (built 2026-11-10): a need makes its task idle with the question and its key (TaskRecord.asked); the agent dropped it and is free. Your answer re-assigns the same task id ("Answer to your question in task …"); while the agent is in a turn on other work, the answer waits (Delivery.later, and hub.send says "delivered: when its agent is free"). Cancelling a question needs no agent. The open questions are handed over on a Hub reload (export_state "questions", TaskBoard.export_questions / restore) and don't hold the reload up. Design: questions are messages.
  • Delivery (delivery.py, built 2026-11-10): the DeliverMessage handler. A message never goes into a turn: into the agent's open task, or a new task if it has none; it waits while the agent is in a turn or not running, and goes when an AgentStateChanged or ModuleStateChanged lets it (flush). Messages to one agent keep their order. What waits is handed over on a reload ("waiting"). Used by cv (the result at Submit) and the gate.
  • The message gate (gate.py, MessageGate, built 2026-11-10): hub.send with agent_id from an agent other than the Talker goes straight into the receiver's open task when that's the caller's child (it interrupts, as before); otherwise through the gate. If the sender's kind has no message:<receiver> grant, a card asks you ("X wants to message Y": Allow once · Always allow · Deny), and the message and later ones from X to Y wait behind it ("waiting on the user's card"). Allow: delivered through Delivery. Deny or no answer: a [messages] note to the sender. "Always" is saved under agent_hub for the sender's kind, one per direction. A reload waits while messages are on a card. Design: messages between agents.
  • Notices and resets (commands since 2026-11-13): AgentNotice puts one line in the agent's next turn through its note. The label is the module that sent it ([job_search], [cv]); only the core's own notices keep their source ([permissions]). ResetRequested calls the agent's own reset (at once when idle, a handoff with a task). Both answer not_available when the agent isn't running. The Talker's own sessions are reset by the Talker (talker.reset), not here.
  • The access-list review (review.py, built 2026-11-13): before an access card shows, the core's permissions handler sends ReviewAccessList (the reviewer's id, who asks, why, the list and its warnings). The Reviewer starts a normal task on that reviewer (the Main Assistant by default, [core.permissions] reviewer) with REVIEW_PROMPT, and sees its end through the board's TaskUpdated (_publish_task shows it to the reviewer first). It always answers the core with AddCardNotes: the reply lines (review_lines: bullets stripped, "No further warnings." dropped, each cut at 300 characters) when the task is done, reviewed=False otherwise. A busy reviewer answers not_available at once; a review past its timeout is cancelled. With no Hub the router answers not_available at once and the card says "not reviewed". stop closes open reviews.
  • The focus (built 2026-11-05): the coordinator at launch, kept across a Hub reload, back to the coordinator when the focused agent stops. The Hub checks on every AgentStateChanged and ModuleStateChanged, and says the move with FocusChanged (previous is the gone agent), so the page leaves the dead tab at once (2026-11-06). A need or permission from an agent out of focus is held (stored once, on its task) until you focus that agent; SetFocus releases it in FocusChanged.
  • The cap and the folder check: besides the coordinator (not counted), at most max_extra_agents agents (3 by default) have an active task at once; a task is refused when its agent's write_folders clash with those of an agent with an active task (folders_clash in tasks.py). The rule (2026-11-13): the same folder always clashes; one folder inside the other clashes too, unless the inner one is in a module's own folder (src/assistant/modules/<id>, found with module_folder_of) and the outer one is above that module folder. So a module's agent editing its own module (its default grant, every module can edit itself) runs beside the Main Assistant's whole-repo grant, while two agents inside one module folder, or a non-module folder in the repo beside the whole repo, are still refused. The refusal names both folders and whose grant holds the other: "b would write …\modules\cv, but a's open task 1a2b3c4d writes …\modules\cv (in a's write grant): the same folder". A task holding a question counts for neither. An active agent is refused (not_available); an idle one stopped on a task drops it (done, "stopped: a new task replaced it").
  • The coordinator's feed: every other agent's milestone, done and failed, and each focus move, go to the coordinator's note, read at the end of its next message. Never an interrupt, never a wake.
  • A child's end to its parent (built 2026-11-12): when a child task ends by its agent's own done or failed (not a cancel), the board (TaskBoard._to_parent) sends the parent task's agent [Message from agent_hub] Your child task <id> on <agent> ended <state>: <result> (cut at 4000 characters), unless the task was started with StartTask.tell_parent=False (kept on the TaskRecord and in its export; cv.task sets it, since cv reports the end as cv.job_finished), through Delivery.tell, so it goes like any DeliverMessage: into its open task, a new task if it has none, or after its turn. Never into a turn, never through the gate (it's the parent's own child). The coordinator as parent gets only its feed line. So a job agent that hands work over (cv.task, hub.start) ends its turn and is woken by the result, without waiting.
  • Duplicate ids, the safety net: two agents with one id (one skipped the claim) are seen once, the first one, in hub.agents, ListAgents and routing, and the clash is logged once. The claims themselves are the core's. Design: agent names.

Agent talkers (built 2026-11-05): each tab has its own Talker; the Hub keeps the focus and every !. While you're in another tab, an agent's questions, replies (TaskInfo.reply) and ends (done, failed) are held (TaskUpdated.held) and released in FocusChanged.released when you open its tab, finished tasks included. hub.send takes an agent_id, so a helper tab's Talker sends to its own agent; other agents use it to message any agent, through the gate.

Flows: task assignment, progress request, clarification, working together.
