html_viewer: the HTML viewer and its app

Purpose

View, edit, highlight and snip HTML files in tabs. html_viewer is the thin module; the viewer app (src/html_viewer) is its own program that doesn't import the assistant. Off at launch, on when used: with start_on_use = true, the first page opened (a SHOW tag, the temp UI's Open in viewer button, any viewer.* call) turns it on through the core, even if you turned it off (start on use). modules.on / modules.off still work. Full design: HTML viewer.

Interface
Menu viewer.open (open a file in a tab), viewer.highlight (open it and highlight a quoted part), viewer.tabs (open files and highlights): tools offered today. The core links it and routes InvokeTool to it, checking the arguments first
Handles nothing
Calls nothing
Publishes ViewerTabsChanged, ViewerClip (a snip, image copied into the launch's log folder)
Listens to nothing
To the app the viewer's local HTTP API (module → app) and its event stream (app → module)

Owns and launches

  • Launches the viewer app on the first show request, through CompanionApp (python -m html_viewer, port 8766), and quits it when the module stops. A viewer you started yourself is left running. On a reload the running viewer is handed to the new copy (its window and tabs stay), unless the viewer's own code changed: then it's quit, even one you started, and the next page shown launches the new code.
  • The app owns the tabs, highlights, snips, editing and saving, including writing text edits back to a generated page's Markdown source (generated folders).
