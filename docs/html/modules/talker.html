talker: the agent that talks with you

Purpose

A fast claude session that talks with you and hands work to the Agent Hub. Tags in its replies become Hub commands and viewer tools. On by default. Design: agents, the Talker on its own.

Wrapper

Field Value
id talker
provides / requires / optional nothing (it reaches the Hub by commands)
permissions none declared

Interface
Tools none
Handles nothing
Calls StartTask, GetTaskStatus, SendToTask, CancelTask, AnswerPermission, SetPermissionMode (Manual only), InvokeTool viewer.open / viewer.highlight
Publishes ResponseReady, SessionUsage, SessionTheme, ResetRequested, ShutdownRequested (restart=True)
Listens to InputReceived, TaskUpdated, SessionUsage, ResetRequested, PermissionModeChanged, ViewerTabsChanged, ViewerClip, ViewerClipDropped

Owns and launches

  • One claude -p process (ClaudeSession), restarted on a ResetRequested for talker.
  • Its transcript in the launch's log folder, and the restart note kept across a <<RESTART>>.
  • The module door (built 2026-11-05): its command line is read at each session start, with IModuleDoor.mcp_config() from the Agent Hub as --mcp-config and all three door tools (list_modules, show_menu, use_item) allowed, since it has no permission cards. The core's risky items still ask the permissions first. Its prompt says to use them for quick things and to hand real work to the worker. SHOW tags stay a shorthand for viewer.open / viewer.highlight. door = false in its config turns it off.

flowchart LR

    Hub["Agent Hub commands"]

    Out["ResponseReady"]

    In --> Inbox --> Claude --> Tags
    Tags --> Hub
    Tags --> Viewer
    Tags --> Out

Everything that should make it speak goes into one inbox, so it never talks over itself and event handlers return at once.
