voice_in: voice input and the voice service

Purpose

Speech to text for the whole app. voice_in is the thin module; the voice service (src/voice_service) is its own app that owns the mic and the speech engines. On by default. Full design: voice.

Interface
Tools none (its menu is empty)
Handles StartListening (send_as_input), StopListening (discard); the result has the final text
Calls nothing
Publishes VoiceState, VoiceTranscript (live and final, with settled_chars), InputReceived (source="voice", only with send_as_input)
Listens to nothing
To the service the /ws/listen protocol, from voice_service.protocol (the only import from the service)

Owns and launches

  • Launches the voice service on the first mic click, through CompanionApp (python -m voice_service, port 8767), and quits it when the module stops. A service you started yourself is left running.
  • One mic session at a time, one WebSocket each. The second press wins: a new StartListening ends the open one with VoiceState(idle, reason="taken_over") and an empty final.
  • The service owns the mic (MicSource, or FileSource / FakeSource), the engines (Zipformer for live text, whisper for the sent text, or two passes cleaned piece by piece by PieceCutter), and mic-drop recovery. Its config is config/voice_service.toml.

A session: StartListening launches the service if needed and opens a socket; the service streams live text, which LiveLine keeps as a settled (cleaned) start and a live rest; StopListening asks for the final, which is cleaned and published, and sent to the Talker only if the session asked for it. Details: the voice_in module, threads and audio flow.

Config

[modules.voice_in]: host, port (8767), start_timeout, service_config, reply_timeout, live_text, final_timeout_on_send, cleanup, terms. The service: config/voice_service.toml (engine choice, mic-drop wait). Command timeouts: [core.command_timeouts] StartListening, StopListening.
