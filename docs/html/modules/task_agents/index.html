task_agents: helper agents launched by name from kinds in config

Purpose

Builds the helper agents beside the Main Assistant from kinds of helper in config. Each helper is a task agent the Agent Hub can start, focus and hold questions for. A helper is launched by name for one task, only with your yes; a kind with autostart = true also starts at launch. Off at launch (turn it on with modules.on). Design: working together, launching a helper.

Wrapper

Field Value
id task_agents
provides ITaskAgent, once per helper (only the Hub calls them)
requires / optional none (uses IAgentNames when the Hub runs)
needs none (Manifest.needs, from its module.toml): a core module, it needs no other module by id; launching a helper goes through the Hub (StartTask)
packages none
permissions agent.access: each kind's access list is asked for on one card (access lists)

Config

Defaults in module.toml in this module's folder, its kinds of helper included: the keys at its top level are defaults for every kind (permission_mode, permission_timeout, chrome = true; never needs or packages), and [agents.<kind>] is one kind. [modules.task_agents] in the app's config (your config/local.toml) only overrides them, key by key: [modules.task_agents.agents.<kind>] there changes the keys it names of a shipped kind, or adds a kind. config/default.toml has no section for it. A kind takes the keys of main_assistant's config plus description, prompt, autostart (start at launch; default false) and instances (how many to autostart). The shipped kinds: helper works in ../assistant-helper (outside the repo, which the Main Assistant writes); rezi (the Rezi helper) in ../assistant-rezi, reading the repo's docs (point it at your own folders in config/local.toml). Neither is autostarted.
