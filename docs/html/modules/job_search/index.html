job_search: the job agent and its menu

Purpose

The job agent, bundled with its own module: one big agent (id job_search_agent) that works in the job project (job project), applies to one job per session and runs job searches, plus its job.* menu. Off at launch (turn it on with modules.on). Design: working together.

Wrapper

Field Value
id job_search
provides ITaskAgent, the job agent (only the Hub calls it)
requires / optional none
permissions agent.access: it asks for its config's access list when turned on (access lists)

Config

[modules.job_search]: ProfileAgent's keys plus agent_id (default job_search_agent: the module id plus _agent; transcript job_search_agent.jsonl). Shipped: workspace C:/Chang/Jobs/CV, reads C:/Chang/Jobs and JobRadar, python (JobRadar's Python, any arguments), tools = "default", chrome = true. These keys are its access list, asked for on one card (access_items). permission_mode takes Manual modes only: every session starts in Manual.

[modules.job_search.ui] (optional, not part of the access list): script (default <workspace>/Recruiters/scripts/job_ui.py), python (default the section's python, JobRadar's, as job_ui.cmd uses), port (8781), page (/tracker). With no script or Python, the agent still runs and job.open_ui says what's missing.
