ModuleProtocol

Reusable · Used by: every module; the core's loader and lifecycle

class ModuleProtocol(ABC)

The one interface every module implements. Set the manifest class attribute and implement init; subclass it to get the do-nothing defaults for the other hooks. It's a protocol, not a Contract: a class is a module by having these members, and nobody looks a module up through the container, so it has no I prefix (principle 12). It carries no behaviour: a module gets its behaviour from the parts it owns (a CompanionApp, a SessionTaskAgent, a Menu).

The core calls init for every module in dependency order, then start for each, and on shutdown stop in reverse order. stop is called for every module whose init succeeded, even if start never ran. If init or start raises, the module is skipped (see lifecycle).

Modules must be restartable. A module can be deactivated and activated while the app runs. Each activation creates a fresh instance and calls init and start again, so stop must release everything the module started (processes, threads, windows, devices), and in-memory state doesn't survive deactivation. Load expensive resources in start or on first use. After stop, the old context drops publish and refuses send. A resource that can't be stopped (like a blocking input() thread) should be shared across instances, as console_io does.

Attributes

Name Type Description
manifest ClassVar[Manifest] Required. Identifies the module and its dependencies
menu ClassVar[Menu | None] Optional, default None. The actions others may call: a Menu the core links to the running copy

ModuleProtocol.init

async init(self, ctx: ModuleContext) -> None

Abstract. Subscribe to events, register command handlers, and provide contracts here. Keep ctx if the module needs it later. Don't start background work yet.

ModuleProtocol.start

async start(self) -> None

Begin active work: listening for input, background loops. Default does nothing.

ModuleProtocol.stop

async stop(self) -> None

Stop work and release resources. Default does nothing. Has core.module_stop_timeout seconds. Subscriptions, handlers, and provided contracts are removed by the core afterwards, so there's no need to undo them here.

Example

class EchoOrchestrator(ModuleProtocol):
    manifest = Manifest(
        id="echo_orchestrator",
        description="Stand-in orchestrator: echoes, /tools",
        optional=(IToolProvider,),
        publishes=(ResponseReady,),
        listens=(InputReceived,),
    )

    async def init(self, ctx: ModuleContext) -> None:
        self._ctx = ctx
        ctx.subscribe(InputReceived, self._on_input)

    async def _on_input(self, event: InputReceived) -> None:
        self._ctx.publish(ResponseReady(text=f"Echo: {event.text}", correlation_id=event.id))

ModuleProtocol.busy

busy(self) -> str | None

Why this module's code shouldn't be swapped right now (for example "replying to you"), or None. A ReloadModule waits until it's None (up to core.reload_idle_timeout), unless it says now. Default None. Today: the Talker (a turn is running), the Agent Hub (tasks open), the Main Assistant (working on a task).

ModuleProtocol.export_state

export_state(self) -> Any

Called before a reload stops this instance. What it returns reaches the new instance as ctx.handover in init (and goes back to the old instance if the new code fails). Return plain data or assistant.infra / app_kit objects, which are never reloaded; never this module's own classes, which change with the code. Default None: the new instance starts clean. A hook that raises counts as None. Today: voice_in hands over its CompanionApp, so the voice app keeps running.

Menu

Reusable · Used by: every module with tools (agent_hub, talker, usage, task_agents, cv, job_search, html_viewer, echo_orchestrator) and the core's own menu; read by the core (MenuTools, ScopedContext.link_menu) and scripts/build_docs.py (the module library)

class Menu() · MenuItem(spec: ToolSpec, method: str, callers=(), takes_caller=False, ask: str | None = None, ask_when: str = "")

A module's menu: the actions an assistant or another module may call. Plain data built when the module's file is imported, so the core reads it without starting the module. Declare one per module class, decorate the methods that are its items, and set it as the class's menu. When the module is on, the core links the menu to that copy (after init) into its private MenuTable and offers its items through InvokeTool; closing the module's context unlinks exactly that copy. A reload re-imports the file, so the reloaded menu runs the new methods. The module never calls ctx.provide(IToolProvider, ...) for it, and menus are never in the container (G16), so no module can call a menu and name its own caller.

Method What it does
item(name, description, properties=None, required=(), callers=(), ask=None, ask_when="") Decorator for an async method taking the item's arguments as keywords and returning a Result (a plain value becomes Result.ok). properties: a JSON Schema per argument. callers: the only module or agent ids allowed to use it (empty: anyone). A method with a caller parameter is passed the caller's id (MenuItem.takes_caller), so it can decide per caller itself; caller can't be one of the item's properties. ask: the core asks you on a confirm card before the call runs, through the ask-first gate: "always" (Auto too) or "risky" (skipped for a caller in Auto); a caller that is you runs at once. ask_when: a boolean property; the card only when that argument is true (modules.off's with_dependents). Raises ValueError at import for a duplicate name, a description that isn't one line, a required name not in properties, an ask other than "always" / "risky" (ASK_MARKS), or an ask_when that doesn't name a boolean property
specs() / names() / items() The items as ToolSpecs, names, or MenuItems (spec, method, callers, takes_caller, ask, ask_when), in declaration order
get(name) -> MenuItem | None One item, or None (the gate reads its ask)
MenuItem.asks(args) -> bool Whether this call goes through the ask-first gate: it has an ask mark and, with ask_when, that argument is true
check(name, args) What's wrong with args, or None: a missing required argument, an unknown one, a wrong type (bool is not an integer), a value outside enum, a string shorter than minLength once trimmed
allowed(name, caller) -> bool Whether caller may use the item
async call(module, name, args, caller="") not_available for a caller the item doesn't allow, then check, then run the item on module (with caller= if it takes it); invalid_arguments when the check fails. The caller comes from InvokeTool.caller

Example

menu = Menu()

class HtmlViewerModule(ModuleProtocol):
    manifest = Manifest(id="html_viewer", description="View, edit, highlight and snip HTML")
    menu = menu

    @menu.item("viewer.open", "Open an HTML file in the viewer",
               {"path": {"type": "string", "minLength": 1}, "front": {"type": "boolean"}}, required=["path"])
    async def show(self, path: str, front: bool = False) -> Result: ...

# an item that asks first (a made-up one: no module item is marked risky today)
@menu.item("notes.clear", "Delete every note", ask="risky")   # a confirm card first, unless the caller is in Auto
async def clear(self) -> Result: ...

Manifest

Reusable · Used by: every module

Manifest(id: str, provides: tuple = (), requires: tuple = (), optional: tuple = (), uses: tuple = (), needs: tuple[str, ...] = (), packages: tuple[str, ...] = (), permissions: tuple[str, ...] = (), optional_permissions: tuple[str, ...] = (), description: str = "", handles: tuple = (), sends: tuple = (), publishes: tuple = (), listens: tuple = (), publishes_named: tuple[str, ...] = (), listens_named: tuple[str, ...] = ())

Frozen dataclass describing a module: who it is, what it needs, and its inputs and outputs. Plain data on the class, read without starting the module (for the dependency graph, the directory and the generated module library). Code dependencies are on contracts, never on other modules; needs only sets the start order: which modules are turned on first (dependencies). permissions and optional_permissions are declarations: single names aren't checked yet (ctx.permissions allows and logs them). agent.access says the module asks for its config's access list with request_set when turned on.

Fields

Name Type Required Description
id str yes Unique id, the name of its folder, used in modules.enabled and for its config (config/<id>.toml)
provides tuple[type[Contract], ...] no Contracts this module provides via ctx.provide
requires tuple[type[Contract], ...] no Contracts that must be provided by an enabled module, or startup fails
optional tuple[type[Contract], ...] no Contracts used if present; only affects start order
uses tuple[type[Contract], ...] no Contracts looked up at each call that may be missing, with no start order: a slot an add-on may fill (IPageOpener), or a provider that itself uses this module, where optional would make a cycle. The core's own contracts (IAgentNames, IModuleDoor) are declared here too
needs tuple[str, ...] no Ids of the modules it can't run without (voice_notes needs voice_in); a module it only chains to for one step isn't listed (job_search turns cv on itself when needed, []). Turning it on turns them on first, at startup too (start order only: a needed module that fails doesn't stop it); turning one off is never refused, and the reply names the modules left on that need it. Usually set in the module's module.toml (needs = [...]): when the file has the key, the core puts it here as the module is loaded (loader.apply_module_toml). A needed id that doesn't exist fails startup (StartupError, the id named) or the activation (not_available). Not its own id
packages tuple[str, ...] no The pip packages its code and its app need, as requirement strings (cv: ("pymupdf>=1.24", "pypdf>=7", "mcp>=2.3", "httpx2>=2.10")). Set in the module's module.toml (packages = [...]), read the same way as needs; each a non-empty string. Informational: nothing installs them, so install them by hand with pip from this list. No module's packages are in pyproject.toml
permissions tuple[str, ...] no Permission names the module can't run without
optional_permissions tuple[str, ...] no Permissions it asks for in the moment; without them a feature is off (voice_in: ("microphone",))
description str no (every module in the app sets it) One line saying what it does, for the directory and the module library
handles tuple[type[Command], ...] no Commands it handles with ctx.handle (commands in). Strict: ctx.handle raises for a type not listed
sends tuple[type[Command], ...] no Commands it sends (commands out). Strict: ctx.send refuses a type not listed
publishes tuple[type[Event], ...] no Events it publishes (events out). Strict: ctx.publish drops a type not listed
listens tuple[type[Event], ...] no Events it subscribes to (events in)
publishes_named tuple[str, ...] no Named events it publishes, each <its id>.<what> (html_viewer, temp_ui, cv)
listens_named tuple[str, ...] no Named events it listens to: <module>.<what>, or <module>.* for all of one module (talker, temp_ui, job_search)

Every type in provides, requires, optional and uses must be a Contract from assistant.contracts, or startup fails. An unlisted handler raises, an undeclared send is refused and an undeclared publish dropped (both logged as errors); a subscription, lookup or named event the manifest doesn't declare still works and is logged once (ScopedContext).

Raises (when the manifest is made): ValueError if id isn't a Python identifier, description has a line break, a publishes_named name isn't <id>.<what>, or a listens_named name isn't <module>.<what> or <module>.*; TypeError if handles / sends hold anything but Command types, or publishes / listens anything but Event types.

own_agent(agent_id, subject) Say that this module's agent agent_id holds subject's grant, so that agent may ask for more with permissions.request (called by ProfileAgent.start when given a subject). Non-abstract; does nothing by default

async confirm(what, action, caller="", reason="", wait=False, risky=False) -> Result Ask you yes or no on a confirm card (PermissionRequested, action="confirm") before a risky step (what: "restart the app"), then run action: a Command (sent by the core, so its sent_by is "core") or an async callable returning a Result. caller: who asks (an agent id; default this module). The caller's id is filled in by the core; a module never passes it (confirm's caller names the agent asking, within this module). Every module's ctx.permissions is a PermissionsPort forwarding to the core's permissions handler. request_set is checked: a module that uses it declares agent.access in its manifest. has and request aren't checked yet: they allow, and log a warning the first time each module uses each name ("not checked yet: allowing voice_in microphone (You clicked the mic)"), then debug lines. Required permissions aren't checked at start yet.

    return Result.failed("microphone not allowed")
granted = await ctx.permissions.request_set(access_items(config), "its folders", subject="job_search_agent")
await ctx.permissions.confirm("restart the app", restart_step, caller=self.id)   # the Talker's RESTART: a card, Auto too

ModuleContext.subscribe

subscribe(event_type: type[E], handler: Callable[[E], Awaitable[None]]) -> SubscriptionHandle

Receive every published event that is an instance of event_type (subclasses included). The handler runs on this subscription's own worker, one event at a time, in order. It is cancelled after core.event_handler_timeout; exceptions are logged. Any time while the module runs. Returns a SubscriptionHandle for unsubscribe. An event type not in listens still works and is logged once.

ModuleContext.publish

publish(event: Event) -> None

Publish an event. Returns immediately and never waits on subscribers. Events are dropped for a subscriber whose queue is full.

Strict (decision D3): an event type the manifest's publishes doesn't list is dropped and logged as an error, not raised. Raises: ValueError for a ModuleEvent: a named event goes only through publish_named, which stamps its source (G15).

ModuleContext.publish_named

Reusable · Used by: cv (cv.job_finished, cv.job_submitted), html_viewer (html_viewer.tabs_changed, html_viewer.clip), temp_ui (temp_ui.clip, temp_ui.clip_dropped)

publish_named(name: str, data: Mapping[str, Any] | None = None) -> None

Publish a ModuleEvent named name, which must be <this module's id>.<what>; the core sets its source. data is copied through JSON, so it holds plain values only and the listener never shares the publisher's objects. Returns immediately, like publish. A name not in publishes_named still goes out and is logged once.

Raises: ValueError for another module's name (or not a name), or data that isn't plain JSON (objects, NaN).

self._ctx.publish_named("cv.job_finished", {"reply_to": "job_search_agent", "job_dir": "...", "state": "done"})

ModuleContext.subscribe_named

Reusable · Used by: job_search (cv.job_finished, cv.job_submitted), talker and temp_ui (the viewer's and temp_ui's snips)

subscribe_named(name: str, handler: Callable[[ModuleEvent], Awaitable[None]]) -> SubscriptionHandle

Receive every ModuleEvent named name, or every one of a module with a trailing .* (cv.*). A filter over one bus subscription to ModuleEvent, so delivery works as for subscribe. Matched by name, not class, so publisher and listener each reload on their own; an event published while this module is off or reloading is missed (the bus keeps nothing). A name not in listens_named still works and is logged once.

Raises: ValueError if name isn't <module>.<what> or <module>.*.

ModuleContext.unsubscribe

Reusable

unsubscribe(handle: SubscriptionHandle) -> None

Drop one subscription, typed or named, without stopping the module; events still queued for it are dropped. Does nothing if it's already gone. Everything left is dropped at the module's stop anyway.

ModuleContext.handle

handle(command_type: type[K], handler: Callable[[K], Awaitable[Result]]) -> None

Become the single handler for command_type. The handler must return a Result. List the type in manifest.handles: if it isn't there, handle raises ValueError and the module fails to start.

Raises: ValueError if the command type already has a handler.

ModuleContext.send

async send(command: Command, timeout: float | None = None) -> Result

Send a command to its handler and wait for the result. Never raises for handler problems; see Result for the outcomes.

Strict, and stamped (decision D3):

  • The command's type must be in the manifest's sends; otherwise invalid_arguments (" must list X in manifest.sends") and an error log.
  • The sender is stamped: Command.sent_by is set to this module's id, and an InvokeTool's caller is too (no exception).
  • Control commands (CONTROL in core/context.py) come only from a caller that is you ([core.permissions] you, today temp_ui), plus the others each one names; anyone else gets failed ("X is a control command: only you … may send it"):
Command Also from
DeactivateModule, RemoveModule nobody else
AnswerPermission, AnswerPermissionRequest a relay of your answer ([core.permissions] relays, today the Talker)
ReloadModule, AddModule a module that provides ITaskAgent (its agent's RELOAD: / ADD_MODULE: line, after your Allow on its card)

Not control commands: ActivateModule (a module's own access card guards its start; job_search turns cv on), CancelTask (it goes through the Hub's menu, which checks the caller), SetPermissionMode (the core's handler lets Auto in only from you, Manual from anyone), ShutdownRequested (the sends check alone). The Talker relays card answers only, never Auto (G17). The core's own menu sends as core, so modules.off and modules.remove from an agent pass this check; the gate's card guards them instead (the core's menu).

Parameters

Name Type Required Description
command Command yes The command to send
timeout float | None no Seconds. Defaults to core.command_timeouts.<Class>, then core.command_timeout

result = await ctx.send(InvokeTool(name="add", args={"a": 1, "b": 2}))

IPageOpener

♻ Reusable · Used by: talker (its SHOW tags), temp_ui (the Open in viewer button), SessionTaskAgent (every worker's SHOW tags), all through open_page / show_page · provided by html_viewer

class IPageOpener(Contract) · from assistant.contracts import IPageOpener

The page-opener slot: opening a page (an HTML file) for you to look at, optionally highlighting a quote on it. It's how the core group opens pages without naming an add-on or its tools ("needs" arrows never point core → add-on, modules). One provider at a time; html_viewer provides it while it's on (ctx.provide at start, ctx.withdraw at stop). A caller declares it in manifest.uses and looks it up at each call, never keeps it (a reload swaps the provider).

async open(path: str, quote: str | None = None, heading: str | None = None, front: bool = False) -> Result

Parameter Description
path The file to open; switches to it if it's already open
quote A short text on the page to highlight and scroll to
heading Look for quote only in the section under this heading
front Bring the window to the front: your own click, not for agents' pages

Returns: ok once the page is open; with a quote, the value has found (False when the quote isn't on the page: the page is open, nothing marked). invalid_arguments for a missing file; failed (retryable) when the viewer can't be reached.

Start on use, by contract: with no provider on, open_page sends StartProvider(contract="IPageOpener"); the core turns on the module that declares it in manifest.provides and has start_on_use = true in its config, then looks again. Still none: not_available, "No page viewer is on".

Example

result = await open_page(ctx, r"C:\docs\page.html", quote="exact words")  # the lookup, the start, the "none" answer
