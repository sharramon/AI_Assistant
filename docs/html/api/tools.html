Tools

Capabilities invocable by name, by the AI or any module. All items: from assistant.contracts import .... Back to the API index.

A module offers tools with a Menu, not by providing IToolProvider itself: the core links each running module's menu to IToolProvider through its adapter MenuTools, so InvokeTool reaches it. IToolProvider stays for providers whose tools change at runtime (a remote client's, later), and for tests.

IToolProvider

Reusable · Used by: the core's MenuTools (every module menu); the core's dispatch_tool, talker, temp_ui and echo_orchestrator call through InvokeTool or list the tools

class IToolProvider(Contract)

A contract for things that offer tools. Any number may be provided (multiple = True). A module with a fixed set of actions uses a Menu instead; providing IToolProvider directly means declaring it in manifest.provides and calling ctx.provide(IToolProvider, self) in init.

IToolProvider.tools

tools(self) -> list[ToolSpec]

Abstract. The tools currently offered. Called on every lookup, never cached, so the list may change at runtime.

IToolProvider.invoke

async invoke(self, name: str, args: dict[str, Any]) -> Result

Abstract. Run tool name. Called by the core when an InvokeTool command arrives for one of this provider's tools, with the command's timeout and cancellation applying.

Returns: a Result. Use Result.invalid_arguments for bad args.

IToolProvider.invoke_as

async invoke_as(self, name: str, args: dict[str, Any], caller: str) -> Result

Not abstract. invoke with the caller (InvokeTool.caller); the core's dispatch_tool calls this. The default ignores caller and calls invoke. MenuTools overrides it to pass the caller to Menu.call. Built 2026-11-05.

Example

class Calculator(ModuleProtocol, IToolProvider):
    manifest = Manifest(id="calculator", provides=(IToolProvider,))

    async def init(self, ctx):
        ctx.provide(IToolProvider, self)

    def tools(self):
        return [ToolSpec(
            name="add",
            description="Add a and b",
            input_schema={"type": "object", "properties": {"a": {"type": "number"}, "b": {"type": "number"}}, "required": ["a", "b"]},
        )]

    async def invoke(self, name, args):
        try:
            return Result.ok(args["a"] + args["b"])
        except KeyError as exc:
            return Result.invalid_arguments(f"missing argument {exc}")

InvokeTool

InvokeTool(name: str, args: dict[str, Any] = {}, caller: str = "") (command)

Run the tool called name. Handled by the core, which routes it to the provider currently offering that tool (invoke_as, with caller).

Who sets caller: the sender's context does. ScopedContext.send overwrites it with the sending module's id, so a module can't pass itself off as another. The one exception is the module that provides IModuleDoor (agent_hub): it passes on the caller its door proved with that session's token (an agent's id, e.g. talker or main_assistant). Menu items use it to decide who may call them (Menu callers).

Returns: the provider's Result, or not_available if no provider offers name, or failed if more than one does.

Example

result = await ctx.send(InvokeTool(name="add", args={"a": 1, "b": 2}), timeout=10)

IModuleDoor

Reusable · Used by: agent_hub provides; main_assistant and talker read it at each session start · built 2026-11-05

class IModuleDoor(Contract), single provider, in assistant.contracts.

Method Does
mcp_config(caller: str) -> dict The --mcp-config for one claude session of caller (the agent's id): the door's stdio relay (mcp_door) with a token made for that caller, or {} while it's down. Pass it to claude_command(mcp_config=...). Every use_item the session makes reaches the menus as an InvokeTool with that caller; a session can't claim another name

The session then has three fixed tools, the same whatever modules are on: mcp__modules__list_modules (one line per module, plus core), mcp__modules__show_menu(module_id) (that module's ToolSpecs) and mcp__modules__use_item(name, args) (InvokeTool). They go through the core, so the directory, the menus' argument checks, permissions and hot swap all apply. Modules never provide or use it: MCP stays at the agents' edge.
