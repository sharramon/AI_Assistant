Reusable · Used by: __main__, tests

setup_logging(settings: dict[str, Any], extra: Sequence[logging.Handler] = ()) -> None

Configure root logging from the [logging] config section. Replaces any existing configuration. extra handlers (e.g. LogSession.handler) are added with the same format.

Settings

LogSession

Reusable · Used by: __main__ (the app log and every transcript)

LogSession(root: str | Path = "logs", now: datetime | None = None, app_log: str = "assistant.log")

The log handler: owns where one app launch's logs go. Nothing reaches disk until the first message's theme: then it creates root/<start time>_<theme>/ (e.g. logs/2026-10-26_03-06-52_can-you-split-the-logs/; -2, -3… added after the time if the name is taken) and writes what its sinks held. A launch without a theme leaves no folder. Design: Logging.

Member Does
root: Path The logs folder
path: Path | None The session folder, None until set_theme
handler: logging.Handler The app log (app_log): pass it to setup_logging
sink(name) -> LogSink The LogSink for the file name in the session folder; one per name
folder() -> Path path once it exists, else root (for the temp UI's Logs button)
set_theme(text) Make the theme folder-safe with theme_slug, create the folder, write what's held. The first usable theme wins; an unusable one ("?!") is ignored
finish() -> Path | None Close the files; returns path. Without a theme, drops what was held, unless the app log had a warning or error: then it's appended to root/no-chat.log. Never raises

Example

session = LogSession("logs")
setup_logging({}, [session.handler])            # held in memory
session.set_theme("Can you split the logs per session?")
session.finish()   # logs/2026-10-26_03-06-52_can-you-split-the-logs

ClaudeSession

Reusable · Used by: talker, main_assistant (a callable command, for the permission mode; env for the edit hook), SessionTaskAgent (set_permission_mode)

ClaudeSession(command: Sequence[str] | Callable[[], Sequence[str]], cwd: str | Path | None = None, log: Logger | None = None, on_event: Callable[[dict], None] | None = None, transcript: str | Path | LogSink | None = None, env: Mapping[str, str] | None = None)

env adds variables to the process's environment, on top of the app's. The Main Assistant uses it so the edit hook can tell its worker apart from your own Claude Code sessions (batching note).

One long-lived claude -p stream-json process. Knows nothing about tasks or agents: it writes messages and interrupts as JSON lines on stdin and hands every JSON line from stdout to on_event, in order. Build command with claude_command. command may be a callable returning the command line: it's called on every start, so each new process gets the settings of that moment (the Main Assistant's permission mode). With transcript, every line in and out (and stderr) is appended to that file as {"t", "dir": "in" | "out" | "stderr", "msg"} JSON lines, for debugging. transcript may be a file path or a LogSink. Modules pass their transcript setting, which __main__ has replaced with the session's sink.

Member Does
async start() Launch the process (no-op if running), reading command if it's a callable. Raises FileNotFoundError if claude isn't installed
async send(text, images=()) Send a user message, starting a turn. images are PNG or JPEG files sent with it as image blocks, so the model sees them; the transcript records their paths, not their data. Raises RuntimeError if not running, OSError if an image can't be read
async interrupt() Interrupt the turn, like Esc. The turn still ends with a result (is_error: true)
async set_permission_mode(mode) Switch the running process's --permission-mode (e.g. acceptEdits) with a set_permission_mode control request, as the Agent SDK does. Applies from the next tool use; the prompt stays as it started. Checked against the real claude (2026-11-02). Raises RuntimeError if not running
async answer_permission(request, allow, message=...) Answer a can_use_tool control request (the whole event); deny sends message
async close(timeout=3.0) Close stdin, wait, kill if it doesn't exit. start works again afterwards. Lines still arriving while it closes are logged, not passed on
running: bool The process is alive
working: bool From send until the turn's result
context_tokens: int The latest call's input size, cached or not (from each assistant line's usage): what every further call resends. 0 after start
used: dict[str, int] Tokens by kind (input, cache_write, cache_read, output), every call since construction, across restarts. Input counts each call once (by message id). Output comes from each turn's result: the streamed lines undercount it (2.5k against 129k in one real session) and only stand in while a turn runs
id: str A new id per ClaudeSession object (kept across process restarts inside it), sent as SessionUsage.session
subagents Each sub-agent's tokens, by agentId, with its type. Taken per turn from the result: its model_usage_since_last_result (or the cumulative modelUsage) less the session's own calls since the last result. Shared among the sub-agents that returned that turn, by last-call size; with none, under unnamed. Without per-turn numbers, each sub-agent's last-call numbers are used. Rows with no tokens yet are left out
on_event Settable callback. Also gets {"type": "exit", "returncode": n} if the process ends on its own

path_rule

Reusable · Used by: main_assistant (one user so far; any agent that gets folder rules)

path_rule(tool: str, folder: str | Path) -> str

A permission rule for everything under folder: path_rule("Edit", "docs") → Edit(//c/Chang/.../docs/**). claude matches absolute paths in POSIX form with a leading //, so Windows C:\x becomes //c/x. Read rules cover Read, Glob, and Grep; Edit rules cover Edit and Write. Checked against a real session: reads and writes inside the rule's folder work without a prompt; writes elsewhere are refused.

SessionTaskAgent

Reusable · Used by: main_assistant, task_agents, job_search (through ProfileAgent)

SessionTaskAgent(session: ClaudeSession, ctx: ModuleContext, agent_id: str, description: str, capabilities: tuple[str, ...] = (), cancel_timeout: float = 5.0, permission_timeout: float = 600.0, fresh_sessions: bool = True, max_handoffs: int = 3, manual_claude_mode: str = "acceptEdits", context_reminder: int = 0, edit_note: bool = False, task_file: str | Path | None = None, write_folders: Iterable[str] = (), compact_handoffs: Callable[[], bool] = lambda: False, close_tabs: Callable[[], bool] = lambda: False)

Working with other agents (built 2026-11-05). write_folders goes into info() for the Hub's folder-clash check (pass AgentProfile.write_folders()). Each STATUS: <line> in the agent's text (status_lines) is reported as a milestone. note(text) adds the line to a MilestoneFeed, whose block goes at the end of the next message the agent writes to its session: a new task, a message (either kind), and every message it sends itself (handoffs, continues, reminders). Never an interrupt, never a turn of its own.

An ITaskAgent backed by one ClaudeSession: the shared part every task agent is built from. Turns assign, message, and cancel into session messages, and the session's events into ReportTask, AgentActivity, AgentStateChanged, and SessionUsage. Sets itself as the session's on_event. Every method returns once its message or interrupt is written. A turn whose last line is NEED: <question> is reported as need. If a cancel's interrupt doesn't end the turn within cancel_timeout, the session is closed and the next task starts a fresh one. A can_use_tool request is reported as permission and held until answer_permission; after permission_timeout seconds it's denied. Behavior: The Main Assistant on its own.

Fresh sessions and handoffs. With fresh_sessions, each task starts in a new claude process, so its context holds only that task. A turn (or a reply) whose last line is HANDOFF: <note path> continues the same task in a fresh session told to read that note; it's reported as progress "Handed off to a fresh session (n): ". After max_handoffs in one task it asks you instead (need), a question like any other: its key is the note, and your answer starts a fresh session pointed at the note, as the first of a fresh allowance, so it asks again only after max_handoffs more. A finished task ends with a plain report, not HANDOFF: (which would continue it).

Handoffs in place, for Chrome agents (built 2026-11-10). Chrome ties an agent's tab group to its claude session id, so a fresh session can't reach the old tabs. When compact_handoffs() is true (ProfileAgent passes lambda: profile.chrome) and the session is live in the current mode, a HANDOFF: keeps the session: it sends /compact (asking the summary to keep the note's path and each tab's id), reports progress "Handed off in place, context compacted (n): ", and on the compact's result sends "Task, continued after your context was compacted …" with the note. Messages that come during the compact are held and added to that message. A failed compact falls back to a fresh session. It counts against max_handoffs like any handoff. A new task still starts fresh.

Closing Chrome tabs at a task's end (built 2026-11-10). When close_tabs() is true (ProfileAgent passes lambda: profile.chrome), the task used a Claude in Chrome tool (mcp__claude-in-chrome__*), and the turn with its final reply called no tabs_close_mcp, the agent holds the done report and sends one more turn (CLOSE_TABS): close the tabs you no longer need, keep any the user should act on, reply in one line. On that turn's result it reports done with the real final text, even if the turn failed. A message during that turn waits for it, then goes in like any message (INTERRUPTED), and the task carries on. A question, a handoff, a cancel or a failure closes nothing. AgentProfile.command allows tabs_context_mcp and tabs_close_mcp with no card for an agent with Chrome, and every agent's prompt has the rule: close a tab once its page is done, and the rest before the final reply.

Questions are messages (built 2026-11-10). Outside, the agent is active or idle (AgentState, info().state). A turn ending NEED: <question> reports need with the question's key (ReportTask.key), drops the task and is idle as soon as the Hub has the report: it takes new work, whatever it asked. The answer comes back as the same task (Task.question_key set): into the live session if that still has the question (nothing ran since), else a fresh session whose first message adds "[App] This is a fresh session …" and the module's notes for the key. A message to a task it has just asked in gets not_available until the report is with the Hub.

Context reminder. With context_reminder (tokens; 0, the default, is off), the first time the session's context passes it during a task, checked with ContextWatch wherever usage is published, the task gets a [Context check] message the same way message sends any (interrupt, then carry on): find a safe point, write what's done and next into the change note, and end with HANDOFF:. Once per crossing: a fresh session starts small and re-arms it. While the task waits on you (a permission request) the reminder is held and sent once it works again, so an open request isn't dropped. Logged (context 152k past 150k: reminded task … to find a reset point) and published as AgentActivity (context reminder sent (152k)).

Edit note. With edit_note, the second edit to a file in a task (Edit, Write, MultiEdit or NotebookEdit, paths compared lowercase with /, counted across handoffs) is logged (batching note for task … : <path> edited twice) and published as AgentActivity (batching note: a.md), once per file. It only reports and never sends the agent anything: the note the agent reads comes from the edit hook, with the tool call. With task_file, the current task's id is written there at each assign, so the hook can count by task across sessions.

SHOW tags. Every <<SHOW: path>> or <<SHOW: path | "quote" | heading>> in the agent's text (read with agent_tags) is sent as InvokeTool viewer.open or viewer.highlight through show_page, in the background; the core turns the viewer on first if it's off (start on use). A failure is logged and published as AgentActivity (couldn't show <path>: <error>). Built 2026-11-05; it was the html_viewer module's job before.

Permission mode. It holds the PermissionMode in memory, Manual at every launch. The owning module builds each session's command for permission_mode (pass the session a callable). A session started in another mode is always replaced at the next task, even if unused. Every switch applies at once. Mid-task, a switch to Manual sends ClaudeSession.set_permission_mode(manual_claude_mode) when the running process is in Auto. A switch to Auto mid-task leaves the process in its Manual mode (the git push block is a launch flag) and the agent answers each can_use_tool itself: allowed, logged as allowed in Auto: …, or, for a PowerShell or Bash command containing git push, refused (refused in Auto: …). An open tool request is answered the same way at the switch. The session gets the new mode's rules (AUTO_ACCESS / MANUAL_ACCESS) at the end of its next message; to Auto mid-turn it's interrupted for them (the usual message path), then carries on. Every switch is logged, published as AgentActivity, and published as PermissionModeChanged.
