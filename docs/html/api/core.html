Core host (internal)

The stable host in assistant.core. Modules never use these directly; they go through ModuleContext. Listed here so nothing gets rebuilt elsewhere. Back to the API index. Design and behavior: core architecture.

App

App(available: Sequence[type[ModuleProtocol]], config: dict[str, Any], config_loader: Callable[[], dict] | None = None, logs: LogSession | None = None, config_dir: str | Path | None = None)

Wires the core together and runs the enabled modules. Construction validates the module selection. Handles InvokeTool (through the ask-first gate), ListModules, GetMenu, StartProvider, the module control commands (including ReloadModule, AddModule and RemoveModule), AnswerPermissionRequest and AddCardNotes (the permissions handler's), SetPermissionMode (_set_mode) and ShutdownRequested (_on_shutdown_requested). A module's ctx.config is its own module.toml defaults with its [modules.<id>] section merged over them (loader.module_defaults, merge); modules.docs reads its own docs/ folder.

config_loader callable no Re-reads the config before a reload, add or remove (__main__ passes load_config)
config_dir str, Path no Where your choices files are, for RemoveModule's purge (config_folder: else ASSISTANT_CONFIG_DIR, else config/); the permissions handler protects it like config/ (writes refused, reads allowed); tests pass a tmp folder
logs LogSession no The launch's log handler; every module reaches it as ctx.logs through a SessionLogs (app.logs). Without it, ctx.logs gives paths under logging.dir

ScopedContext

ScopedContext(manifest, router, bus, container, config, log, handover=None, logs=None, permissions=None, you=(), relays=(), menus=None)

The ModuleContext implementation. Records every subscription, handler, provided contract and linked menu made through it. Sets the module's ctx.permissions to permissions: App passes a PermissionsPort bound to the module's id and the app's handler (without one, a bare PermissionsPort(module_id)). Sets its ctx.logs to the app's SessionLogs (a default one if none is given). you and relays: the Callers port's (App passes callers.you / callers.relays), for the control-command check. menus: the app's MenuTable (a fresh one if none).

Method Description

Card actions. A card's action is a CardAction (ACCESS, GRANT, REVOKE, MESSAGE, CONFIRM; a StrEnum inside the core whose values are PermissionRequested.action's). An answered card is applied by its action's handler from a table (principle 20): access saves the list (and turns the module on); grant and revoke carry out an agent's call and tell it with an AgentNotice; message settles the waiting ask (_apply_message, with Card.remember from the answer); confirm runs the step on Allow, nothing on Deny, and tells you and the caller (_apply_confirm, _run_step). Every PermissionChanged is built in one place. Notices go through _notify: an AgentNotice command (source="permissions"); with no Hub it only logs.

The review is a listener's job (decision D6). _review sends ReviewAccessList (sender: the core) with the card's labels and warnings, and waits up to review_timeout + REVIEW_GRACE (5 s) for AddCardNotes; it keeps at most MAX_REVIEW_LINES (8) notes, source="review". not_available (no Hub, or the reviewer is busy) shows the card "not reviewed" at once. The core never starts a task. It does cancel one: _stop_tasks sends GetTaskStatus / CancelTask when a revoke turns a module off.

Saved grants: GrantStore and Grant (store.py), one section per module and subject in config/permissions.toml (GRANTS_FILE; gitignored), written whole and atomically; copy_old_grants(new, old) copies the old data/permissions.toml (OLD_GRANTS) across once at startup when the new file is missing, leaving the old one in place; fingerprint(items) hashes a list's keys. Guardrails: PROTECTED, refusals, rule_warnings and FIXED_RULES (rules.py).

dispatch_tool

async dispatch_tool(container: Container, menus: MenuTable, command: InvokeTool, start_on_use: Callable[[str], Awaitable[Result | None]] | None = None, off_owner: Callable[[str], str | None] | None = None, confirm: Confirm | None = None) -> Result

The InvokeTool handler. Looks up providers at call time, in menus and among the container's IToolProviders (modules that provide it themselves still count); returns not_available for an unknown tool, failed for a name offered twice, else the provider's result. off_owner: the id of a module that is off and has the tool on its menu, so the answer is "The module isn't on …" (module_off_text).

confirm (decision D4): the one ask-first gate. Confirm = Callable[[caller, what, run, risky], Awaitable[Result]]. For an item whose MenuItem.asks(args) is true, the arguments and callers are checked first (a bad call never reaches a card), then confirm(caller, "<name> (<k>: <v>, …)", run, item.ask == "risky"). For any other menu item, Menu.call makes the same checks. Start on use (below) runs before these checks, so a caller the item's callers refuses can still switch an off start_on_use module on. App passes lambda caller, what, run, risky: app.permissions.confirm("core", caller, what, run, risky=risky).

♻ Reusable · Used by: every InvokeTool caller: talker (the Hub's menu), temp_ui (its menu calls), the agents' door (use_item). Pages (SHOW, Open in viewer) go through IPageOpener instead, and their start on use is StartProvider (by contract, the same App._start_on_use).

Start on use: when nobody offers the tool, App passes start_on_use=App._start_for_tool. It finds the module that is off, has the tool on its menu, and has start_on_use = true in its [modules.<id>] config, and turns it on the same way as ActivateModule (LifecycleManager.activate, with what it requires); then the call goes ahead. A failed start answers failed with "The module couldn't start: …" (retryable; the next call tries again). Calls that arrive while it's starting wait on the lifecycle's lock and find it on, so it starts once. A module you turned off is started again too. Only html_viewer sets it. StartProvider uses the same search (App._start_on_use), matching a contract in manifest.provides instead of a tool on the menu.

CoreMenu

CoreMenu(send, permissions: ModulePermissions, docs=None)

The core's own menu (modules.*), id core (CORE_ID; no module may use it). App builds one with the router's send, PermissionsPort("core", app.permissions) and its module-docs reader (as app.core_menu), and adds it to the MenuTable through a MenuTools (app.core_menu_tools) in the name core from start to stop. App also handles GetMenu. modules.add, modules.remove, modules.reload are marked ask="always" and modules.off ask="always", ask_when="with_dependents": the gate asks, and the items' own code asks nothing. Each item sends its control command as core, so the gate's card, not the control-command check, is what stands between an agent and the command; modules.off without dependents shows no card.
